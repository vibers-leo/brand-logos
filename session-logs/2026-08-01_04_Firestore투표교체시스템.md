# 2026-08-01 (4차) — Firestore 투표·교체 시스템 구축

## 세션 개요
- 프로젝트: brand-logos (logo.vibers.co.kr)
- 핵심 결과: 버전 비교 패널에 👍 투표 + 🔄 교체 요청 기능 추가. Firebase Firestore 연동 완료.

## 주요 작업

### 1. Firebase SDK 연동 (index.html)

`<head>` 에 Firebase v10 모듈 스크립트를 type="module"로 추가.
initializeApp + getFirestore 를 실행한 뒤 `window._logoVotes` 에 DB 인스턴스와 함수들을 노출하고,
`firebaseReady` 이벤트를 dispatch해 기존 스크립트(non-module)에서 감지할 수 있게 설계.

```js
window._logoVotes = { db, doc, getDoc, updateDoc, setDoc, increment };
window.dispatchEvent(new Event('firebaseReady'));
```

### 2. 버전 비교 패널 UI 개편

각 소스 카드(`src-card`) 하단에 두 버튼 추가:
- **👍 N표** 버튼 (`vote-btn`): 클릭 시 castVote() 호출, Firestore 증가 + localStorage로 1기기 1표 보장
- **🔄** 버튼: 클릭 시 requestSwap() 호출, confirm() 확인 후 Firestore에 교체 요청 기록

교체 요청된 카드에는 amber(#f59e0b) outline으로 시각적 표시.

### 3. JavaScript 함수 추가

| 함수 | 역할 |
|------|------|
| `loadVotes(brandId)` | 패널 열릴 때 Firestore에서 투표 수 조회, 버튼에 반영 |
| `castVote(brandId, file, btn)` | 투표 기록. localStorage 중복 체크. |
| `requestSwap(brandId, file, btn)` | 교체 요청. swap_pending=true, swap_target=file 저장 |
| `showToast(msg)` | 공통 토스트 알림 (기존 pickSource 토스트 중복 제거) |

Firestore 컬렉션 구조:
```
logo_votes/{brandId}:
  votes: { "sources/fa.svg": 5, "sources/iconify/react.svg": 12 }
  swap_pending: boolean
  swap_target: string | null
  applied_at: timestamp (교체 완료 후)
```

### 4. collect-auto.py — apply_votes() 함수 추가

`python3 collect-auto.py --source apply-votes` 실행 시:
1. Firestore에서 swap_pending=True 인 브랜드 조회
2. swap_target 파일을 logo.svg 또는 logo.png로 복사
3. 기존 파일은 logo.bak.{ext}로 백업
4. SVG 교체 시 cairosvg로 logo.png 재생성
5. brands.json의 sources[] 배열에서 해당 소스를 index 0으로 이동
6. Firestore swap_pending=False, applied_at=now() 로 초기화

Firebase Admin SDK 인증:
- `.firebase-sa.json` 파일 우선 (brand-logos 폴더 루트에 저장)
- 없으면 `FIREBASE_SERVICE_ACCOUNT_KEY` 환경변수에서 JSON 파싱
